# Module contracts (v1)

Static app, **no build step, no ES modules, no fetch**: it must work by double-clicking `index.html` (file://).
Every JS file is a classic script that attaches ONE global and, when `module.exports` exists, also exports it (so node tests can `require` it):

```js
(function (root) {
  const X = { /* ... */ };
  if (typeof module !== 'undefined' && module.exports) module.exports = X;
  else root.X = X;
})(typeof window !== 'undefined' ? window : globalThis);
```
Scripts are loaded in this order by `index.html`: `js/vendor/d3.min.js`, `js/vendor/topojson-client.min.js`, `data/bundle.js`, `js/i18n.js`, `js/store.js`, `js/stats.js`, `js/quiz.js`, `js/map.js`, `js/app.js`.
Code style: 2-space indent, `const`/`let`, no frameworks, no comments except for non-obvious logic.

## Data (`data/bundle.js`, generated by `scripts/build_data.py`)
`window.GeoData = { provincias, ccaa, paises, maps: { world, provincias, ccaa } }`
- `provincias`, `ccaa`, `paises`: the arrays in `data/*.json` unchanged. (`paises` entry: `iso_a3, iso_n3, name_es, name_en, capital_es, capital_en, continent ('europa'|'america'|'asia'|'oceania'|'africa'), capital_lat, capital_lon, disputed`.)
- `maps.world`: TopoJSON from `data/maps/world-50m.topo.json` (object `countries`, feature `id` = `iso_n3` string, 3 digits). `maps.provincias`/`maps.ccaa`: the GeoJSON FeatureCollections (`properties.id` = province INE code "01".."52" / ccaa id).
- node tests load the JSON files directly and set `globalThis.GeoData`.

## Topics (`Quiz.TOPICS`)
`[{ id, group: 'spain'|'world'|'locate', labelKey }]` with ids:
`es_ccaa_cap` (capitales de comunidades autónomas), `es_ccaa_prov` (a qué comunidad autónoma pertenece una provincia), `world_europa`, `world_america`, `world_asia`, `world_oceania`, `world_africa`,
`loc_prov`, `loc_ccaa`, `loc_europa`, `loc_america`, `loc_asia`, `loc_oceania`, `loc_africa`.
`labelKey` is a key in `i18n.js`.

## quiz.js → `Quiz`
`Quiz.generate(topicId, count, rng = Math.random)` → array of up to `count` questions (fewer only if the topic has fewer items, e.g. Oceania = 14), no item repeated within a game.
```js
{
  topic, kind: 'mc' | 'locate',
  itemKey,                    // stable id of the asked item, e.g. 'pais:068', 'prov:09', 'ccaa:cataluna'
  prompt: { es, en },
  options: [{ id, label: {es, en} }],   // mc only: exactly 5, one correct, shuffled; labels never duplicated
  answerId,                   // mc: id of the correct option
  target: { layer: 'provincias'|'ccaa'|'world', id, city: { lat, lon, name: {es,en} } | null },
  mapView: 'spain' | 'europa' | 'america' | 'asia' | 'oceania' | 'africa'
}
```
- `es_ccaa_cap`: the 17 comunidades autónomas (Ceuta and Melilla are excluded: they are ciudades autónomas). Both directions mixed 50/50: "¿Cuál es la capital de X?" (comunidad → capital) and "¿De qué comunidad autónoma es capital Y?" (capital → comunidad). Distractors come from the other comunidades' capitals/names. `target` = the comunidad (layer ccaa), city = its capital (for Canarias the label is 'Las Palmas de Gran Canaria / Santa Cruz de Tenerife'; place the dot at Las Palmas de Gran Canaria's coordinates from provincias.json, id 35).
- `es_ccaa_prov`: all 50 provinces, one kind: "¿A qué comunidad autónoma pertenece la provincia X?" / "Which autonomous community is the province of X in?". Options = 5 comunidades (the correct one plus 4 others, no Ceuta/Melilla; prefer geographic neighbours when easy, else random). `answerId` = ccaa id, `target` = the comunidad (layer ccaa), city = the province's capital (lat/lon from provincias.json) so the map shows both the comunidad and where the province capital is. Plays at most 50.
- `world_<continent>`: country → capital and capital → country, 50/50. Distractors prefer the same continent. Exclude `disputed` countries as the *asked* item, but they may not appear as options either. `target.layer='world'`, `id` = iso_n3, city = capital, `mapView` = continent.
- `loc_*`: `kind:'locate'`, no options; `answerId` = target id; prompt "¿Dónde está X?"/"Where is X?". `loc_prov` → layer provincias, `loc_ccaa` → ccaa, `loc_<continent>` → world countries of that continent, excluding `disputed`. Locate questions have `city: null`.
- Item `itemKey` for a country is `pais:<iso_n3>`, province `prov:<id>`, comunidad `ccaa:<id>`.
- Deterministic with a seeded `rng` (tests rely on it).

## store.js → `Store`
`Store.create(storage)` returns a store bound to a `getItem/setItem` storage (falls back to in-memory on any exception); `window.Store` is `Store.create(window.localStorage)` created lazily inside try/catch. Data lives under key `geografia.v1` as one JSON object `{ players: { [name]: { games: [Game] } }, settings: { lang } }`.
```js
Game = { topic, count, correct, total, date /* ISO string */, answers: [{ itemKey, correct: bool }] }
store.listPlayers()                 // names sorted case-insensitively
store.addPlayer(name)               // trims; case-insensitive duplicate → returns the existing canonical name; empty/ >24 chars → throws Error
store.recordGame(player, game)      // validates fields, appends
store.getGames(player)              // Game[] oldest first
store.allGames()                    // { [player]: Game[] }
store.getSetting(k) / store.setSetting(k, v)
store.removePlayer(name)
```

## stats.js → `Stats` (pure functions, no storage access)
```js
Stats.topicSummary(games)                    // { [topic]: { games, correct, total, pct /*0-100 rounded 1 decimal*/, bestPct } }
Stats.ranking(allGames, topic, minTotal=10)  // [{ player, pct, total, games }] sorted by pct desc then total desc; players with total < minTotal excluded
Stats.mostMissed(games, n=5)                 // [{ itemKey, missed, seen }] sorted by missed desc, then miss rate
Stats.streak(games)                          // current run of consecutive correct answers across games, newest backwards
Stats.progress(games, topic)                 // [{ date, pct }] oldest first
Stats.lastGames(games, n=5)                  // newest first
Stats.overall(games)                         // { games, correct, total, pct }
```

## map.js → `GeoMap`
`const m = GeoMap.create(containerEl, { lang })` then:
```js
m.setLang(lang)
m.show({ view, layer, targetId, city, clickedId, correct })   // static result map: draws the view, highlights the target, marks the city dot+label (name in current lang) if city, and the wrong clicked area in red if clickedId !== targetId
m.locate({ view, layer, onPick(id) })                         // interactive: areas hoverable/clickable, zoom/pan (wheel, drag, +/− buttons), small countries get a larger invisible hit target plus a marker circle; onPick fires once, then clicks are ignored until the next locate()/show()
m.reveal({ targetId, clickedId })                            // after onPick: highlights target green, clicked wrong area red, zooms to include the target
m.destroy()
```
- `view`: `'spain'` or a continent. Spain: conic conformal for peninsula + Baleares + Ceuta/Melilla, **Canarias in a framed inset** (bottom-left). Continents: `d3.geoNaturalEarth1` fitted to fixed lon/lat boxes: europa [-25,33,65,72], america [-170,-57,-30,75] (rotate as needed), asia [25,-11,180,78], oceania [110,-48,180,5] plus the Pacific east of the date line via `rotate([-150,0])`, africa [-20,-36,52,38]. Clip to the viewport.
- All views share one visual system defined in `css/map.css` via CSS variables, in light and dark: sea, land, border, hover, target (amber `#f0a21a`), correct (green `#2e9e5b`), wrong (red `#d64545`), city dot. Same border widths, fonts and label style everywhere. The mapped layer's own neighbours are drawn as plain land (e.g. in `world` views all countries are drawn; in `spain` views all provinces/comunidades).
- Disputed borders (Kosovo, Taiwan, Palestine, Western Sahara, N. Cyprus, Somaliland) are drawn with a dotted border and are never clickable targets.
- Must be responsive (SVG `viewBox`, redraw on container resize).

## i18n.js → `I18n`
`I18n.t(key, lang, vars?)`, `I18n.lang` get/set persisted through Store; dictionaries `es` and `en` covering every UI string of `mockup/layout.html` plus the splash and topic labels. Missing key → returns the key (and `console.warn` once).

## app.js (UI)
Implements exactly the screens, flow and styles of the approved `mockup/layout.html` (player → menu → quiz → result → stats) and the 5-second skippable splash of `mockup/splash.html`, wired to the modules above:
- splash (5 s, click/Space skips) → player screen. ES/EN toggle in the header on every screen; the choice is stored with `Store.setSetting('lang')`.
- Menu groups: España (`es_ccaa_cap`, `es_ccaa_prov`), Mundo (5 continents), Situar en el mapa (`loc_*`), count 10/20/30. If a topic has fewer items than the count chosen, play all of them.
- mc screen: question, 5 buttons, after answering colour right/wrong, show `GeoMap.show(...)` map on the right (below on phones), feedback text and a "Siguiente" button; **Space triggers Next**; keys 1-5 pick an option. Under the progress bar: "Pregunta n/N" left, "xx % aciertos" (running % correct) right.
- locate screen: `GeoMap.locate` fills the card; after the click `GeoMap.reveal`, feedback text, Next (Space).
- result screen: n/N and %, buttons Repetir / Menú; the game is saved through `Store.recordGame` when the last answer is given.
- stats screen: per-topic % table, ranking per topic (all players, `Stats.ranking`), last 5 games, most missed (names resolved from `GeoData` by `itemKey`), streak, progress line chart (inline SVG).
- Accessible: buttons are real `<button>`s, focus visible, `lang` attribute updated, reduced-motion respected.

# Central scores (Google Sheet) — v2 additions

## Game ids
`Game` gains an optional `id` (string, unique per game; `Sync.newId()`). `Store.recordGame` accepts and keeps it.

## config.js → `GeoConfig`
`window.GeoConfig = { sheetUrl: '' }`. Empty string = local-only mode (no network calls at all). The family pastes the Apps Script web-app URL here.

## stats.js additions
```js
Stats.overallRanking(allGames, minTotal=10)  // [{ player, pct, total, games }] over ALL topics, same sort/min rule as ranking()
Stats.merge(local, central)                  // both { [player]: Game[] }; returns { [player]: Game[] } union; games with the same id are counted once (central wins); games without id are kept as-is; players matched case-insensitively (canonical name = first seen); each list sorted oldest first by date
```

## sync.js → `Sync`
`Sync.create({ url, storage, fetch })`; `window.Sync = Sync.create({ url: GeoConfig.sheetUrl, storage: localStorage (try/catch → in-memory), fetch: window.fetch })`.
```js
sync.enabled()                 // !!url
sync.newId()                   // crypto.randomUUID() when available, else timestamp+random
sync.submitGame(player, game)  // queue { player, game } (game must have id) under storage key 'geografia.queue.v1', then flush(); resolves, never rejects
sync.flush()                   // sends queued items one at a time, in order: fetch(url, { method:'POST', headers:{'Content-Type':'text/plain;charset=utf-8'}, body: JSON.stringify({ player, game }) }); dequeue only when response JSON has ok:true; on any failure stop and keep the rest; no concurrent flushes; resolves { sent, pending }
sync.pending()                 // number of queued items
sync.fetchAll()                // GET url + '?action=list'; resolves { [player]: Game[] } (rows grouped by player) or null when disabled/failed
```
Apps Script protocol (`apps-script/Code.gs`): `doPost(e)` parses `e.postData.contents` → `{ player, game }`, validates (player 1–24 chars, topic ≤40 chars, integers with 0 ≤ correct ≤ total ≤ 100, ISO date, answers array ≤100 items, payload ≤ 20 KB), ignores a duplicate `game.id`, appends a row `[id, player, topic, count, correct, total, date, answers-as-JSON]` under `LockService`, returns JSON `{ ok: true }` or `{ ok: false, error }`. `doGet(e)` with `action=list` returns `{ ok: true, games: [{ id, player, topic, count, correct, total, date, answers }] }`. The script creates its own spreadsheet "Geografía – Scores" on first use (SpreadsheetApp.create, id stored in PropertiesService script properties) and a header row.

## app.js changes
- On finishing a game: `game.id = Sync.newId()`, `Store.recordGame` locally, then `Sync.submitGame` (fire and forget).
- Stats screen: fetch `Sync.fetchAll()`, show "loading…", then rankings from `Stats.merge(Store.allGames(), central)`; per-topic ranking (existing) plus a new **overall ranking**; highlight the current player's row; medals/numbers for the top 3; a small status line ("Synced with the family scoreboard" / "Offline: showing this device only" / "n games waiting to sync"); when `Sync.enabled()` is false, show only local data without any status line.
- The player screen's existing-player list stays local, but when central data loads, also offer players found centrally (so a family member on a new device can pick their name).
- New i18n strings in ES and EN.

## v3 changes
- Topics `es_prov` and `es_ccaa` are removed (replaced by `es_ccaa_cap` and `es_ccaa_prov` above). Games already stored under old topic ids must be ignored by the stats screens/rankings (only topics in `Quiz.TOPICS` are listed), never crash.
- GeoMap: zoom and pan (mouse wheel / pinch, drag, +/− buttons) work in EVERY map, including `show()` result maps and after `reveal()`; double-click/double-tap zoom in; dragging never triggers a pick; touch devices pan with one finger (`touch-action` must allow it inside the map without scrolling the page when the map is zoomed).
